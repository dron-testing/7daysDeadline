## Тема 0. Как устроена программа и как её запустить

Программа на Котлине это текстовый файл с расширением `.kt`. Компьютер начинает выполнять её с особой функции `main` (по-английски «главная»). Это **точка входа**: если её нет, запускать нечего.

```kotlin
import kotlin.math.PI   // подключаем число π из математической «коробки»

fun main() {            // fun = «функция», main = её имя, () = пока без параметров
    println(PI)         // выводим число π в консоль
}                       // фигурные скобки { } ограничивают тело функции
```

Разберём, что здесь встретилось:

- `fun` ключевое слово, которое говорит «сейчас я объявляю функцию». Ключевые слова нельзя использовать как свои имена.
- `{ }` фигурные скобки задают **блок кода**: всё между ними относится к одной функции, условию или циклу.
- `import` подключает то, что лежит в другом месте. В Котлине готовые инструменты разложены по пакетам (как по коробкам). Базовые вещи (`println`, `listOf`, `String`) доступны сразу, а например число π из пакета `kotlin.math` нужно подключить строкой `import kotlin.math.PI`. Импорты пишутся самым первым в файле, выше всего остального.
- Точка с запятой в конце строки не нужна. Каждая команда обычно пишется с новой строки.
- Котлин различает регистр: `Main`, `main` и `MAIN` для него три разных имени.

### Как запустить код в IDEA

1. В окне **Project** нажмите правой кнопкой на папку `src` (или `src/main/kotlin`) и выберите **New → Kotlin Class/File**.
2. Выберите вариант **File** и дайте имя, например `Task1`.
3. Напишите в файле `fun main() { ... }`.
4. Нажмите зелёный треугольник слева от `fun main()` и выберите **Run**. Результат появится в окне **Run** внизу.

### Полезные приёмы в IDEA

- `Alt+Enter` на красной подчёркнутой строке показывает варианты исправления, в том числе «добавить import».
- `Ctrl+Space` подсказывает, какие методы есть у объекта после точки.
- `Ctrl+Alt+L` выравнивает код по правилам.
- `Ctrl+/` закомментирует выделенные строки (повторное нажатие уберёт комментарий).

В каждом файле может быть свой `main`, так что задания удобно делать в отдельных файлах. Но если в двух файлах вы объявите класс с одинаковым именем (например, `Product`), IDEA покажет ошибку `Redeclaration`: дайте таким классам разные имена.

## Тема 1. Вывод в консоль и комментарии

**Вывод** это способ показать результат работы программы человеку. Консоль это окно **Run** внизу IDEA.

```kotlin
println("Привет!")
```

Разбор этой строки:

- `println` имя **функции** (готовой команды). Название сокращение от print line, «напечатай строку».
- `( )` круглые скобки: в них передают то, с чем функция должна работать. Это называется **аргумент**.
- `"Привет!"` текст в двойных кавычках. Такой кусок текста называется **строкой** (String). Кавычки нужны, чтобы Котлин понял, что это текст, а не команда.

Разница между вариантами:

- `print("A")` печатает без перехода на новую строку, следующий вывод пойдёт сразу за ним.
- `println("A")` печатает и переходит на новую строку.
- `println()` без аргумента просто пропускает строку.

Есть важная разница между текстом и числом. `println(5 + 5)` выведет `10`, потому что Котлин сначала посчитает. А `println("5 + 5")` выведет буквально `5 + 5`, потому что в кавычках всё остаётся как есть.

### Специальные символы в тексте

Внутри строки обратная косая черта `\` означает «дальше идёт спецсимвол»:

| Запись | Что делает |
| --- | --- |
| `\n` | перенос строки |
| `\t` | табуляция (отступ) |
| `\"` | кавычка внутри текста |
| `\\` | сам символ обратной косой черты |

```kotlin
print("Кофе\tЦена\n")        // Кофе   Цена и переход на новую строку
println("Он сказал: \"Привет\"") // Он сказал: "Привет"
```

### Комментарии

**Комментарий** это пометка для человека, которую Котлин пропускает. Она объясняет, зачем написан код, и помогает вам через неделю вспомнить, что вы имели в виду.

```kotlin
// Однострочный комментарий: действует до конца строки

/*
   Многострочный комментарий:
   действует, пока не встретится закрывающая пара.
*/
```

Комментарии ещё используют, чтобы временно «выключить» код, не удаляя его. В ваших файлах с курса весь старый код спрятан внутри `/* ... */`, чтобы запускалась только новая часть. Это удобный приём. Заметьте, что в Котлине многострочные комментарии можно вкладывать друг в друга, как у вас в первом файле.

## Тема 2. Переменные и типы данных

**Переменная** это коробка с ярлыком: на ярлыке написано имя, внутри лежит значение. Через имя вы потом достаёте значение или кладёте новое.

```kotlin
val a = 1
var b = 2
b = 5
```

Разбор:

- `val` и `var` ключевые слова, которые создают переменную.
- `a` и `b` имена, которые придумываете вы.
- Знак `=` здесь означает не «равно», а «положи в коробку». Читайте `val a = 1` как «создай коробку a и положи в неё 1».
- Строка `b = 5` кладёт в уже существующую коробку новое значение, поэтому слово `var` второй раз не пишется.

Два вида переменных:

- `val` (value, «значение») **неизменяемая**. Положили один раз, поменять нельзя. Попытка вызовет ошибку `Val cannot be reassigned`.
- `var` (variable, «переменная») **изменяемая**. Значение можно менять сколько угодно.

Правило хорошего тона: по умолчанию пишите `val`, а `var` только там, где значение реально меняется. Так в программе меньше неожиданных поломок.

### Правила для имён

- Только буквы, цифры и `_`, цифра не может быть первой.
- По традиции имена переменных начинаются с маленькой буквы, а несколько слов склеиваются «верблюдом»: `cardBalance`, `userName`. Это называется camelCase.
- Имя должно говорить, что внутри: `price` лучше, чем `x`.

### Типы данных

**Тип** определяет, что можно хранить в переменной и что с ней можно делать. Нельзя положить текст в коробку для чисел.

| Тип | Что хранит | Пример |
| --- | --- | --- |
| `Int` | целое число (примерно от −2,1 млрд до +2,1 млрд) | `val x = 5` |
| `Long` | очень большое целое число | `val y = 10L` (буква L в конце) |
| `Double` | дробное число (основной тип для дробей) | `val p = 3.14` |
| `Float` | дробное число поменьше и поточнее | `val f: Float = 4.6F` (буква F в конце) |
| `Boolean` | только `true` (правда) или `false` (ложь) | `var ok = true` |
| `String` | текст в двойных кавычках | `val s = "Привет"` |
| `Char` | один символ в одинарных кавычках | `val c = '3'` |

Обратите внимание: `"3"` это строка (String), а `'3'` это символ (Char). Дробная часть пишется через точку, а не запятую: `4.6`.

### Явный и неявный тип

Котлин умеет угадывать тип по значению. Это **неявный тип**: `val c = 5` значит `Int`. Но тип можно указать **явно** через двоеточие: `val d: Long = 10`. Двоеточие читается как «имеет тип».

Явный тип нужен, когда Котлин не может угадать сам или вы хотите другой тип, чем по умолчанию (например, `Long` вместо `Int`). Чтобы узнать, какой тип угадал Котлин, наведите мышь на имя переменной в IDEA.

### Важный нюанс про деньги

Дробные числа в компьютере хранятся приближённо: например, `0.1 + 0.2` даст `0.30000000000000004`. Для учебных заданий `Double` подходит. В настоящих банковских программах для денег используют специальные типы вроде `BigDecimal`, но это уже за рамками курса.

## Тема 3. Арифметика, преобразование типов, строки

### Арифметика

| Знак | Что делает | Пример | Результат |
| --- | --- | --- | --- |
| `+` `-` `*` | сложение, вычитание, умножение | `6 * 7` | `42` |
| `/` | деление | `7 / 2` | `3` (оба числа целые!) |
| `%` | остаток от деления | `7 % 2` | `1` |

Главная ловушка: если делить **целое на целое**, дробная часть отбрасывается. `7 / 2` это `3`, а не `3.5`. Чтобы получить дробь, хотя бы одно число должно быть дробным: `7 / 2.0` даёт `3.5`.

Остаток от деления полезен, чтобы проверять кратность: `n % 2 == 0` значит «n чётное», `sum % 100 == 0` значит «сумма кратна 100».

Порядок действий как в школе: сначала `*` и `/`, потом `+` и `-`. Скобки меняют порядок: `(1 + 2) * 3`.

**Сокращённая запись** для изменения переменной (она должна быть `var`):

```kotlin
var counter = 0
counter += 5   // то же, что counter = counter + 5  → 5
counter -= 1   // то же, что counter = counter - 1  → 4
counter++      // увеличить на 1  → 5
counter--      // уменьшить на 1  → 4
```

Ещё есть `*=` и `/=`. Помните про переполнение: `Int` не вмещает числа больше примерно 2,1 млрд, для них берите `Long`.

### Преобразование типов

Котлин строгий: он не склеивает `Int` и `Double` молча, преобразование нужно написать самому. Для этого у любого числа есть методы `toInt()`, `toLong()`, `toDouble()`, а у любого значения `toString()`.

```kotlin
val i = 100
val d = i.toDouble()       // 100.0
val n = 3.99.toInt()       // 3, дробная часть отбрасывается, а не округляется
val x = "123".toDouble()   // строка превратилась в число 123.0
```

Здесь появилась **точка** после значения: `i.toDouble()`. Точка означает «возьми у этого значения умение (метод) и примени». Так вы будете вызывать методы у всего: чисел, строк, списков, ваших объектов.

Осторожно: `"abc".toInt()` или `"3,5".toDouble()` вызовут ошибку и программа упадёт. Как безопасно разбирать ввод, мы разберём в теме 4.

### Строки

Методы и свойства строки (после точки):

```kotlin
val text = " Kotlin "
text.length              // 8, длина (без скобок, это свойство)
text.trim()              // "Kotlin", убрать пробелы по краям
text.uppercase()         // " KOTLIN "
text.lowercase()         // " kotlin "
text.contains("tli")     // true
text.replace("K", "k")   // " kotlin "
text[1]                  // 'K', символ по номеру (нумерация с 0)
```

Склеивать строки можно знаком `+`: `"Привет, " + name`. Но удобнее **строковые шаблоны**.

### Строковые шаблоны и знак доллара

Знак `$` внутри строки означает «вставь сюда значение переменной». Так не нужно клеить текст через `+`.

```kotlin
val name = "Никита"
val age = 24

println("Меня зовут " + name + ", мне " + age + " лет")   // через +, неудобно
println("Меня зовут $name, мне $age лет")                  // через $, удобно
println("Мне будет ${age + 10}, в имени ${name.length} букв")
```

- `$name` вставляет значение переменной `name`.
- `${ ... }` с фигурными скобками нужны, когда внутри не просто имя, а **выражение**: вычисление (`age + 10`) или вызов через точку (`name.length`). Если написать `$name.length`, подставится только имя, а `.length` останется просто текстом.
- Чтобы напечатать сам знак доллара, поставьте перед ним косую черту: `"Цена: 5\$"`.

### Многострочные строки

Тройные кавычки позволяют писать текст на нескольких строках как есть, с переносами:

```kotlin
val text = """
    Первая строка
    Вторая строка
"""
println(text.trimIndent())   // trimIndent убирает общий отступ слева
```

### Сравнение строк

Знак `==` проверяет, одинаковы ли строки по содержимому, а `!=` наоборот. Регистр важен: `"kotlin" == "KOTLIN"` это `false`. Чтобы сравнить без учёта регистра, приведите обе к одному: `a.lowercase() == b.lowercase()`, или напишите `a.equals(b, ignoreCase = true)`.

### Красивый вывод дробных чисел

Дробь может вывестись некрасиво (`8510.638297872341`). Шаблон формата `%.2f` оставляет два знака после запятой:

```kotlin
val result = 20000 / 2.35
println("%.2f".format(result))   // 8510.64
```

Расшифровка: `%` значит «здесь будет подставлено число», `.2` два знака после точки, `f` дробное число. Если в вашей системе стоит русская локаль, разделителем может оказаться запятая, это нормально.

## Тема 4. Ввод с консоли

Пока что все данные у вас вписаны прямо в код. Чтобы программа работала с тем, что вводит человек, используют `readln()` (read line, «прочитай строку»). Программа остановится и будет ждать, пока пользователь что-то напечатает в окне **Run** и нажмёт Enter. Перед вводом нужно кликнуть мышью в это окно.

```kotlin
println("Введите имя")        // подсказка человеку, иначе он не поймёт, чего ждёт программа
val myName = readln()         // то, что ввели, сохранилось в переменную
println("Привет, $myName!")
```

`readln()` всегда возвращает **строку**, даже если человек ввёл цифры. Чтобы работать с числом, строку нужно преобразовать:

```kotlin
val age = readln().toInt()          // ввели 24 → число 24
val temp = readln().toDouble()      // ввели 36.6 → число 36.6
```

Здесь два вызова идут цепочкой: сначала `readln()` читает строку, потом к ней применяется `.toInt()`.

### Что если человек ввёл не число

Если ввести `abc`, а программа ждёт число, она упадёт с ошибкой `NumberFormatException`. Безопасный вариант: `toIntOrNull()` и `toDoubleOrNull()`. Они возвращают число, а если не получилось, то специальное значение `null` («ничего»). Что это такое, подробно в теме 8, а пока достаточно знать, как с этим работать:

```kotlin
val number = readln().toIntOrNull()
if (number == null) {
    println("Это не число")
} else {
    println("Вы ввели число $number")
}
```

### Несколько значений в одной строке

Метод `split` разрезает строку по разделителю и возвращает **список** частей. Затем список можно «распаковать» в отдельные переменные:

```kotlin
val (digit1, digit2) = readln().split(" ")   // ввели: 10 20
println("Число 1 = $digit1, Число 2 = $digit2")
```

- `split(" ")` разрезает по пробелу: из `"10 20"` получится список из двух строк `"10"` и `"20"`.
- `val (a, b) = ...` называется **деструктуризацией**: первая часть списка идёт в `a`, вторая в `b`.
- `digit1` и `digit2` здесь остаются **строками**, поэтому для арифметики нужны `digit1.toInt()` или `toDouble()`.
- Если человек введёт меньше частей, чем переменных, программа упадёт. Лишние пробелы тоже ломают результат, поэтому учебные программы просят вводить ровно по формату.

## Тема 5. Условия: if и when

До сих пор программа выполняла все строки подряд. **Условие** позволяет выбирать: если выполняется одно, делаем одно, иначе другое.

### Логические выражения

Выражение, результат которого `true` или `false` (тип `Boolean`), называется **логическим**. Его дают операторы сравнения:

| Знак | Значение |
| --- | --- |
| `==` | равно (два знака, не путайте с `=`, который кладёт значение) |
| `!=` | не равно |
| `>` `<` | больше, меньше |
| `>=` `<=` | больше или равно, меньше или равно |

Их можно объединять:

| Знак | Название | Когда `true` |
| --- | --- | --- |
| `&&` | И | оба условия верны |
| `\|\|` | ИЛИ | верно хотя бы одно |
| `!` | НЕ | меняет `true` на `false` и наоборот |

Например, `age >= 18 && hasTicket` значит «совершеннолетний и с билетом».

### if, else if, else

```kotlin
val temp = readln().toDouble()

if (temp > 25) {
    println("Жарко")
} else if (temp < 0) {
    println("Холодно")
} else {
    println("Нормально")
}
```

- Условие пишется в круглых скобках после `if`.
- Код в фигурных скобках выполняется, только если условие верно.
- Проверки идут сверху вниз и останавливаются на первой сработавшей. Ветки `else if` и `else` необязательны.
- Если в ветке всего одна команда, фигурные скобки можно опустить (как в вашем примере с `println("Холодно")`), но со скобками безопаснее.

### if как выражение

У `if` есть особенность Котлина: он может **вернуть значение** и записать его в переменную. Результатом ветки становится её последняя строка.

```kotlin
val status = if (temp > 15) "тепло" else "прохладно"

val desc = if (temp > 15) {
    println("Проверяю...")   // можно выполнить действия
    15                       // а последняя строка станет значением
} else {
    temp.toInt()
}
```

У `if`-выражения обязательно должна быть ветка `else`, иначе Котлин не будет знать, что положить в переменную.

### when вместо длинной цепочки if

`when` («когда») сравнивает одно значение с разными вариантами. Каждая строка читается как «если значение такое, то результат такой»:

```kotlin
val day = readln().toInt()

val result = when (day) {
    1 -> "Понедельник"           // конкретное значение
    2 -> "Вторник"
    in 3..5 -> "Среда, четверг или пятница"   // in = «входит в диапазон»
    6, 7 -> "Выходной"           // несколько значений через запятую
    else -> "Это не день недели" // всё остальное
}
println(result)
```

- Стрелка `->` отделяет вариант от результата.
- `in 3..5` означает «число от 3 до 5 включительно» (диапазоны разберём в следующей теме). Есть и обратное: `!in`.
- Ветка `else` обязательна, когда `when` возвращает значение.

`when` можно писать и без значения в скобках, тогда в каждой ветке стоит своё условие:

```kotlin
val size = when {
    balance < 10_000 -> "Стандарт"
    balance < 100_000 -> "Серебро"
    else -> "Золото"
}
```

Подчёркивание в числе (`10_000`) Котлин игнорирует, оно нужно только для читаемости.

## Тема 6. Диапазоны и циклы

**Цикл** повторяет блок кода много раз, чтобы не копировать его вручную. Самые частые случаи: перебрать числа, перебрать элементы списка, повторять, пока не выполнится условие.

### Диапазоны

**Диапазон** это последовательность чисел от начала до конца.

```kotlin
1..5           // 1, 2, 3, 4, 5  (конец включён)
1 until 5      // 1, 2, 3, 4     (конец НЕ включён)
5 downTo 1     // 5, 4, 3, 2, 1  (в обратную сторону)
1..10 step 2   // 1, 3, 5, 7, 9  (с шагом 2)
```

`..` это оператор «от и до». Слова `until`, `downTo` и `step` пишутся без точки и скобок, но на самом деле это обычные функции. Такая запись называется **инфиксной** и нужна, чтобы код читался почти как английская фраза. Проверка вхождения: `5 in 1..10` даёт `true`, а `15 !in 1..10` тоже `true`.

### for: перебор

```kotlin
for (i in 1..3) {
    println("Шаг $i")
}
```

Читается так: «для каждого `i` из диапазона от 1 до 3 выполни блок». Переменная `i` создаётся сама, на каждом круге в ней лежит следующее число. Имя можно выбрать любое, традиционно `i`. Перебирать можно не только числа:

```kotlin
val cities = listOf("Москва", "Казань")
for (city in cities) {        // по элементам списка
    println(city)
}
for (ch in "kotlin") {        // по символам строки
    println(ch)
}
for (i in cities.indices) {   // по номерам элементов: 0, 1
    println("$i: ${cities[i]}")
}
```

### repeat: просто N раз

```kotlin
repeat(5) {
    println("Hi!")
}
```

Когда число повторов известно, а сам номер круга не нужен, `repeat` короче `for`. Если номер нужен, внутри блока он доступен как `it` (считается с 0).

### while и do-while: пока условие верно

```kotlin
var n = 0
while (n < 100) {     // условие проверяется ДО каждого круга
    n += 25
    println(n)
}

var m = 0
do {                  // тело выполнится минимум один раз
    m += 25
    println(m)
} while (m < 100)     // условие проверяется ПОСЛЕ круга
```

- `while` может не выполниться ни разу, если условие с самого начала ложно.
- `do ... while` выполнится как минимум один раз. Удобно для задач «спросить, а потом проверить ответ».
- Главная опасность: если внутри цикла не менять переменную из условия, он станет **бесконечным**. Остановить программу можно красным квадратом в окне Run.

### Управление циклом

```kotlin
for (i in 1..10) {
    if (i == 3) continue   // пропустить этот круг и перейти к следующему
    if (i == 7) break      // выйти из цикла полностью
    println(i)             // выведет 1, 2, 4, 5, 6
}
```

- `break` выходит из ближайшего цикла (при вложенных циклах только из внутреннего).
- `continue` пропускает остаток текущего круга.
- `return` выходит из всей функции. Если вы пишете в `main`, это завершит программу целиком.

## Тема 7. Функции

**Функция** это именованный блок кода, который можно вызывать много раз. Представьте кухонный комбайн: вы кладёте продукты (**параметры**), нажимаете кнопку (**вызов**) и получаете результат (**возвращаемое значение**). Функции нужны, чтобы не копировать один и тот же код и чтобы разбить большую программу на понятные кусочки.

### Из чего состоит функция

```kotlin
fun sum2(a: Int, b: Int): Int {
    return a + b
}
```

- `fun` ключевое слово «создаю функцию».
- `sum2` имя функции (придумываете сами, по правилам имён переменных).
- `(a: Int, b: Int)` **параметры**: то, что функция принимает. У каждого указывается имя и тип через двоеточие. Тип параметров обязателен.
- `: Int` после скобок тип результата, который функция вернёт.
- `return` отдаёт результат и сразу завершает функцию. Всё, что написано после `return`, не выполнится.

Функции пишут вне `main`, выше или ниже неё, порядок не важен. Вызов выглядит так:

```kotlin
fun main() {
    val result = sum2(5, 6)   // 5 и 6 это аргументы: конкретные значения параметров
    println(result)           // 11
    println(sum2(10, 20))     // результат можно сразу вывести
}
```

Разница в словах: **параметры** это переменные в объявлении функции (`a`, `b`), **аргументы** это значения, которые вы передаёте при вызове (`5`, `6`).

### Функция, которая ничего не возвращает

Если функция только что-то делает (например, печатает), тип результата не пишут:

```kotlin
fun sum1() {
    println(5 + 5)
}
```

На самом деле такая функция возвращает специальное значение `Unit` («ничего полезного»), но писать его не нужно.

### Короткая запись

Если тело функции это одно выражение, можно писать через `=` без `return` и фигурных скобок. Тип результата Котлин определит сам:

```kotlin
fun sum3(a: Int, b: Int) = a + b
```

### Параметры по умолчанию и именованные аргументы

Если у параметра задано значение, его можно не передавать:

```kotlin
fun create(a: Int, b: Int = 10) {
    println(a + b)
}

create(5)        // b не указан, берётся 10 → 15
create(5, 9)     // b заменили → 14
create(a = 5, b = 9)   // именованные аргументы: понятно, что есть что
```

Именованные аргументы пригодятся, когда параметров много и легко перепутать порядок. Параметры со значением по умолчанию принято ставить в конец списка.

### Локальные переменные

Переменные, объявленные внутри функции, существуют только внутри неё. Снаружи они недоступны: так функции не мешают друг другу.

```kotlin
fun hello() {
    val message = "Привет"   // видно только внутри hello
}
// здесь message уже не существует
```

Функции могут вызывать друг друга: одна функция считает, другая красиво печатает результат первой.

## Тема 8. Null-безопасность

**null** это специальное значение «здесь ничего нет». Оно появляется в реальной жизни постоянно: у пользователя не заполнено поле телефона, поиск ничего не нашёл, введённая строка не превратилась в число. Во многих языках обращение к `null` приводит к самой частой ошибке программ. Котлин решает это на уровне языка: по умолчанию переменная **не может** быть `null`.

```kotlin
var a: String = "Привет"
a = null              // ОШИБКА: String не может хранить null

var b: String? = "Привет"   // вопросительный знак после типа разрешает null
b = null                    // так можно
```

Знак `?` в типе читается как «может быть пустым». Тип `String?` (nullable) и тип `String` для Котлина разные.

### Как безопасно работать с nullable

Если написать `b.length`, Котлин откажется компилировать: вдруг там `null`. Нужно явно сказать, что делать в этом случае. Есть три способа.

| Что | Название | Что значит |
| --- | --- | --- |
| `b?.length` | безопасный вызов | если `b` не null, вернёт длину, иначе вернёт `null` и не упадёт |
| `b?.length ?: 0` | оператор Элвиса | если слева `null`, возьмёт значение справа |
| `b!!.length` | небезопасный вызов | «я уверен, что тут не null»; если там null, программа упадёт с ошибкой |

```kotlin
var name: String? = "James"
println(name?.length)          // 5
println(name!!.length)         // 5, работает, потому что там не null

name = null
println(name)                  // null
println(name?.length)          // null, а не ошибка
println(name?.length ?: 0)     // 0, подставили запасное значение
println(name?.length ?: "New James")  // можно подставить и другого типа
```

Оператор `?:` называют оператором Элвиса (если повернуть голову, он похож на причёску певца). Он берёт левую часть, если она не `null`, иначе правую.

У `!!` ошибка называется `NullPointerException`. Это то, чего Котлин пытается избежать, поэтому `!!` в своём коде старайтесь не использовать. Исключение: быстрые учебные проверки, где вы точно знаете, что значение есть.

### Проверка через if

Можно и классически проверить на null. Внутри ветки Котлин уже «знает», что значение не пустое, и разрешает с ним работать без `?.`:

```kotlin
val phone: String? = readlnOrNull()
if (phone != null) {
    println("Длина номера: ${phone.length}")   // здесь phone уже точно String
} else {
    println("Телефон не указан")
}
```

### Где вы встретите null

- `list.getOrNull(100)` вернёт `null`, если такого индекса нет.
- `"abc".toIntOrNull()` вернёт `null`, если строку нельзя превратить в число.
- Поля в ваших классах, которые могут быть не заполнены.

## Тема 9. Коллекции: List, Set, Map, Array

**Коллекция** это «контейнер», в котором лежит много значений сразу. Хранить 1000 оценок в 1000 отдельных переменных нереально, а в одной коллекции легко. В Котлине четыре основных вида.

| Вид | Особенность | Создание |
| --- | --- | --- |
| `List` | порядок важен, повторы разрешены | `listOf(1, 2, 2)` |
| `Set` | только уникальные значения | `setOf(1, 2, 2)` → `1, 2` |
| `Map` | пары «ключ → значение» | `mapOf("a" to 1)` |
| `Array` | массив фиксированного размера, элементы меняются | `arrayOf(1, 2, 3)` |

Функции `listOf`, `setOf`, `mapOf` создают **неизменяемые** коллекции: добавить или удалить элемент нельзя. Про изменяемые версии в следующей теме.

### List: список

```kotlin
val cities = listOf("Москва", "Казань", "Саратов", "Сочи", "Саратов")

println(cities)               // [Москва, Казань, Саратов, Сочи, Саратов]
println(cities.size)          // 5, размер (свойство, без скобок)
println(cities[2])            // Саратов, элемент по номеру (индексу)
println(cities.first())       // Москва
println(cities.last())        // Саратов
println(cities.indexOf("Сочи"))   // 3, на каком месте лежит
println("Казань" in cities)   // true, есть ли такой элемент
println(cities.isEmpty())     // false, пустой ли список
println(cities.getOrNull(100))    // null, а не ошибка
println(cities.distinct())    // список без повторов
```

Важно: нумерация элементов (**индексов**) начинается с нуля. У списка из 5 элементов номера 0, 1, 2, 3, 4. Обращение `cities[5]` вызовет ошибку `IndexOutOfBoundsException`. Поэтому `getOrNull` безопаснее, если не уверены.

### Угловые скобки в типах

В записи вроде `List<String>` угловые скобки показывают, какого типа элементы лежат внутри: «список строк». Обычно писать это не нужно, Котлин определит сам. Но вы увидите такую запись в параметрах функций и в классах, например `List<Animal>`.

### Set: множество

```kotlin
val cities2 = setOf("Москва", "Казань", "Саратов", "Москва", "Сочи", "Сочи")
println(cities2)               // [Москва, Казань, Саратов, Сочи], повторы выброшены
println("Казань" in cities2)   // true
```

Set удобен, когда нужны уникальные значения или быстрая проверка «есть ли такой». Из списка множество получают так: `list.toSet()`.

### Map: словарь

В Map каждому **ключу** соответствует одно **значение**, как слову в словаре соответствует перевод. Ключи не повторяются.

```kotlin
val capitals = mapOf(
    "Россия" to "Москва",
    "Франция" to "Париж",
    "Великобритания" to "Лондон"
)

println(capitals.keys)           // [Россия, Франция, Великобритания]
println(capitals.values)         // [Москва, Париж, Лондон]
println(capitals["Франция"])     // Париж
println(capitals["Испания"])     // null, такого ключа нет
println(capitals["Испания"] ?: "неизвестно")   // запасное значение

for ((country, capital) in capitals) {    // перебор пар
    println("$country → $capital")
}
```

- `"Россия" to "Москва"` слово `to` склеивает ключ и значение в пару (это такая же инфиксная функция, как `step` или `until`).
- Результат `capitals[ключ]` может быть `null`, если ключа нет. Поэтому тип результата nullable, и тут пригодится `?:` из прошлой темы.

### Array: массив

```kotlin
val array = arrayOf(1, 2, 3, 4, 5)
array[0] = 100               // элемент менять можно
println(array.size)          // 5, а вот размер изменить нельзя
```

Запомнить различие: у `List` нельзя менять ни состав, ни элементы (ни «снаружи», ни «внутри»), у `Array` менять элементы можно, но размер зафиксирован. На практике чаще пользуются списками.

## Тема 10. Изменяемые коллекции

Обычные `listOf`, `setOf`, `mapOf` нельзя менять после создания. Чтобы добавлять и удалять элементы, нужны **изменяемые** (mutable, «способные меняться») версии: `mutableListOf`, `mutableSetOf`, `mutableMapOf`.

### MutableList

```kotlin
val people = mutableListOf("Борис", "Анна", "Никита")

people.add("Ерм")            // в конец: Борис, Анна, Никита, Ерм
people.add(1, "Светлана")    // на позицию 1: Борис, Светлана, Анна, Никита, Ерм
people.removeAt(2)           // удалить по номеру: убрали Анну
people.remove("Борис")       // удалить по значению: убрали Бориса
people[0] = "Евгений"        // заменить элемент по номеру
println(people)

people.clear()               // очистить совсем
```

Ещё есть `addFirst(x)` («в начало») и `addLast(x)` («в конец»), которые вы видели в файле курса. Если IDEA подчёркивает их красным (так бывает в старых версиях Kotlin или JDK), замените их на `add(0, x)` и `add(x)`, результат тот же.

У целочисленных списков легко перепутать: `remove(5)` удаляет **значение** 5, а `removeAt(5)` удаляет элемент под **номером** 5.

### MutableSet и MutableMap

```kotlin
val tags = mutableSetOf("kotlin", "java")
tags.add("kotlin")      // повтор: ничего не произойдёт, в Set только уникальные
tags.add("git")
tags.remove("java")

val prices = mutableMapOf("кофе" to 150, "чай" to 100)
prices["булочка"] = 80  // добавить новую пару
prices["кофе"] = 170    // изменить цену у существующего ключа
prices.remove("чай")    // удалить пару по ключу
```

### Почему `val` и изменяемый список не противоречат друг другу

Слово `val` запрещает **заменить переменную другим списком**, но не мешает менять содержимое самого списка:

```kotlin
val list = mutableListOf(1, 2)
list.add(3)            // можно: меняем содержимое
// list = mutableListOf(9)   // нельзя: пытаемся подменить сам список
```

Поэтому для изменяемых коллекций почти всегда пишут `val`.

### Список можно передавать в функции

Если передать изменяемый список в функцию и изменить его внутри, изменения останутся и снаружи, потому что функция работает с тем же самым списком, а не с копией. Это пригодится в задании:

```kotlin
fun addTrack(playlist: MutableList<String>, track: String) {
    playlist.add(track)
}
```

Тип `MutableList<String>` читается как «изменяемый список строк». А обычный `List<String>` в функции менять нельзя.

### Осторожно при удалении в цикле

Нельзя удалять элементы из списка, пока вы его же перебираете через `for`: Котлин завершит программу ошибкой `ConcurrentModificationException`. Вместо этого используйте `removeAll { условие }` или перебирайте копию (`for (x in list.toList())`).

## Тема 11. Лямбды, фильтрация, сортировка, агрегация

У коллекций много готовых «умений». Чтобы пользоваться самыми мощными, нужно понять одну новую запись.

### Лямбда: мини-функция в фигурных скобках

**Лямбда** это короткая функция без имени, которую передают другой функции как инструкцию. Выглядит так:

```kotlin
val words = listOf("Hello", "World", "my", "name", "is", "Nikita")
println(words.filter { it.length > 5 })    // [Nikita]
```

Разбор: `filter` проходит по всем словам и для каждого спрашивает, подходит ли оно. Вопрос записан в фигурных скобках `{ it.length > 5 }`. Слово `it` («это») означает **текущий элемент**, с которым сейчас работает функция. Если читать вслух: «оставь те слова, у которых длина больше пяти». Результат это **новый список**, исходный не меняется.

### Фильтрация и преобразование

```kotlin
words.filter { it.length > 3 }       // оставить подходящие: [Hello, World, name, Nikita]
words.map { it.lowercase() }         // преобразовать каждый элемент: [hello, world, ...]
words.map { it.length }              // из слов получить длины: [5, 5, 2, 4, 2, 6]
words.any { it == "is" }             // есть ли ХОТЯ БЫ ОДИН подходящий → true
words.all { it.length > 1 }          // подходят ли ВСЕ → true
words.none { it == "hi" }            // НЕ подходит НИ ОДИН → true
words.count { it.length == 2 }       // сколько подходящих → 2
words.firstOrNull { it.startsWith("N") }  // первый подходящий или null → Nikita
words.forEach { println(it) }        // выполнить действие для каждого
```

`map` (преобразовать) и `filter` (отобрать) это два главных инструмента. Они не изменяют исходный список, а возвращают новый.

### Сортировка

```kotlin
val digits = listOf(5, 6, 2, 6, 9, 2, 132, 9, 210)
digits.sorted()                      // по возрастанию
digits.sortedDescending()            // по убыванию
words.sortedBy { it.length }         // по возрастанию ДЛИНЫ слова
words.sortedByDescending { it.length }   // по убыванию длины
```

В `sortedBy` в скобках вы объясняете, **по какому признаку** сравнивать элементы. Исходный список остаётся как был.

### Агрегация: свести к одному числу

```kotlin
digits.sum()        // сумма
digits.average()    // среднее арифметическое (всегда Double)
digits.min()        // наименьшее
digits.max()        // наибольшее
digits.sumOf { it * 2 }   // сумма после преобразования каждого
```

На пустом списке `min()` и `max()` вызовут ошибку. Если список может оказаться пустым, берите `minOrNull()` и `maxOrNull()`: они вернут `null`.

### Срезы: взять часть списка

```kotlin
digits.take(4)        // первые 4
digits.takeLast(4)    // последние 4
digits.drop(4)        // всё, кроме первых 4
digits.dropLast(3)    // всё, кроме последних 3
digits.chunked(2)     // разбить на группы по 2: [[5, 6], [2, 6], ...]
```

### Цепочки

Главная сила в том, что вызовы можно соединять точками, и каждый работает с результатом предыдущего:

```kotlin
val top = digits.filter { it > 5 }.sortedDescending().take(3)   // три самых больших из тех, что больше 5
println(top.joinToString(", "))    // склеить в строку через запятую: 210, 132, 9
```

Найдите: общую выручку, среднюю, лучший и худший день, сколько «провальных» дней (меньше 1000), топ-3 дня по выручке, а также разбейте на недели по 3 дня через `chunked`. ## Тема 12. Классы и объекты

До сих пор данные были разрознены: имя в одной переменной, цена в другой. Когда нужно описать **сущность** из реального мира (товар, пользователя, машину), всё её данные и умения собирают в один **класс**.

- **Класс** это чертёж: он описывает, какие данные и какие умения будут у всех сущностей этого вида. Имя класса пишут с большой буквы (`Car`, `Product`).
- **Объект** (или **экземпляр**) это конкретная вещь, созданная по чертежу. Из чертежа `Car` можно сделать сколько угодно машин.
- **Свойства** (поля) это переменные внутри класса, то есть данные объекта.
- **Методы** это функции внутри класса, то есть умения объекта.

### Самый простой класс

```kotlin
class OldCar {
    var wheel: Int = 4
    var steeringWheel = true
    var brand = "Lada"
}

fun main() {
    val car1 = OldCar()        // создаём объект: имя класса со скобками
    val car2 = OldCar()
    car2.brand = "Moskvich"    // точка даёт доступ к свойству объекта
    println(car1.brand)        // Lada
    println(car2.brand)        // Moskvich
}
```

Обратите внимание: у каждого объекта свои значения свойств, `car1` и `car2` не мешают друг другу. Слова `new`, как в некоторых других языках, в Котлине не нужно.

### Конструктор: задать данные при создании

Параметры в скобках после имени класса называются **первичным конструктором**. Если перед параметром стоит `val` или `var`, он автоматически становится свойством:

```kotlin
class Car(var brand: String, val wheel: Int = 4, val power: Double) {

    init {
        // выполнится один раз при создании объекта
        println("Создана машина $brand")
    }

    fun ride() {                      // метод
        println("Едет $brand")
    }

    override fun toString(): String {
        return "brand: $brand, wheel: $wheel, power: $power"
    }
}

fun main() {
    val car = Car("Volga", power = 4.4)   // wheel пропущен: возьмётся 4
    car.ride()
    println(car)                          // вызовется toString()
}
```

Что здесь нового:

- `var brand` значит, что `brand` свойство, которое можно менять. `val wheel` значит свойство только для чтения.
- Значения по умолчанию (`wheel: Int = 4`) работают как у функций. Если пропускаем параметр в середине, остальные нужно передавать по имени: `power = 4.4`.
- Блок `init` (от initialization, «подготовка») выполняется автоматически один раз сразу при создании объекта. Туда кладут проверки и стартовые действия.
- Параметр конструктора **без** `val`/`var` (например `class A(x: Int)`) не станет свойством: его видно только внутри `init`. А переменная, объявленная внутри `init`, существует только там.
- Внутри методов свойства объекта доступны по имени, как `brand` в `ride()`.
- Метод вызывают через точку: `car.ride()`.

### toString: как объект выглядит в тексте

Если напечатать объект без своего `toString`, получится нечитаемое `Car@1b6d3586`. Когда вы пишете `override fun toString()`, вы **переопределяете** (заменяете) стандартную версию этого метода своей. Слово `override` обязательно: оно говорит «я сознательно меняю уже существующее поведение». Теперь `println(car)` покажет то, что вернёт ваш метод. Подробнее про `override` в теме про наследование.

### Объекты в списках

```kotlin
val cars = listOf(Car("Lada", power = 90.0), Car("Volga", power = 110.0))
for (car in cars) car.ride()
val total = cars.sumOf { it.power }    // работаем со свойствами через лямбду
```

Обычные объекты сравниваются по **ссылке**: `Car("A", power = 1.0) == Car("A", power = 1.0)` даст `false`, потому что это две разные машины. Как сравнивать по содержимому, мы увидим в теме про `data class`.

## Тема 13. Инкапсуляция

Представьте банкомат: вы не лезете руками в хранилище с деньгами, а нажимаете кнопки. Банкомат сам проверяет, хватает ли денег, и только потом выдаёт их. **Инкапсуляция** это то же самое в коде: данные объекта прячут от внешнего мира, а доступ к ним даёт только через методы, где можно сделать проверки.

Без этого любой кусок программы мог бы написать `account.balance = -1000000`, и никто бы не заметил.

### private: закрыть доступ

Модификатор `private` («приватный») делает свойство или метод видимым **только внутри самого класса**. Снаружи компилятор откажется его использовать. Противоположность `public` («публичный»), он стоит по умолчанию, поэтому писать его не нужно.

```kotlin
class Person(var name: String, private var age: Int) {

    // геттер (от get, «получить»): метод, который отдаёт значение закрытого свойства
    fun getAge(): Int {
        return age
    }

    // сеттер (от set, «установить»): метод, который меняет значение, да ещё с проверкой
    fun setAge(age: Int) {
        if (age > 0) {
            this.age = age    // this.age: свойство класса, age: параметр метода
        }
    }
}

fun main() {
    val person = Person("Тайлер", 30)
    person.name = "Расказчик"   // name публичное: можно менять напрямую
    // person.age = 5           // ОШИБКА: age приватное
    person.setAge(29)
    println(person.getAge())    // 29
}
```

Слово `this` («этот») означает «сам этот объект». Оно нужно, когда имя параметра совпадает с именем свойства: `this.age` свойство объекта, а просто `age` параметр метода. В остальных случаях `this` можно не писать.

### Более удобный способ в Котлине

Вместо отдельных методов `getX` и `setX` в Котлине принято выносить проверку прямо в свойство:

```kotlin
class Person(val name: String) {

    var lastName: String = "Дерден"
        private set            // читать можно всем, менять только внутри класса

    var age: Int = 0
        set(value) {           // свой сеттер: вызывается при age = ...
            if (value >= 0) field = value   // field это «сама коробка» свойства
        }
}

fun main() {
    val p = Person("Тайлер")
    p.age = 25           // сработает сеттер, значение 25 корректно
    p.age = -5           // сеттер не пропустит, останется 25
    println(p.age)       // 25
    println(p.lastName)  // читать можно
    // p.lastName = "X"  // ОШИБКА: set приватный
}
```

- `private set` означает: читать значение могут все, а изменять только сам класс. Это очень частый приём.
- `set(value) { ... }` это свой сеттер. Слово `value` это то, что пытаются записать, а `field` обращение к самой «коробке» свойства. Нельзя писать `age = value` внутри сеттера age: это вызовет сеттер снова и приведёт к бесконечному кругу.
- Для чтения обращение `p.age` выглядит как обычное обращение к свойству, хотя за ним может стоять метод.

Главное правило: **закрывайте всё, что снаружи менять не нужно**, и давайте доступ только через методы с проверками.

## Тема 14. Наследование

Представьте, что вам нужны классы собаки, кошки, бобра. У всех есть имя, возраст и умение издавать звук. Писать это три раза глупо. **Наследование** позволяет описать общее один раз в классе-родителе, а в классах-потомках добавить только отличия. Потомок автоматически получает все свойства и методы родителя.

### Как это записывается

```kotlin
open class Animal(val name: String, var age: Int) {
    open fun sound() {
        println("Животное $name издаёт звук")
    }
}

class Dog(name: String, age: Int) : Animal(name, age) {
    override fun sound() {
        println("Гав-гав")
    }
}

class Rat(name: String, age: Int) : Animal(name, age) {
    override fun sound() {
        super.sound()          // вызвать версию родителя
        println("И ещё пищит")
    }
}
```

Разбор новых слов:

- `open` перед `class` разрешает от этого класса наследоваться. В Котлине по умолчанию классы закрыты, чтобы случайно ничего не сломать.
- `open` перед `fun` разрешает потомкам заменить этот метод.
- Двоеточие после имени класса читается как «наследуется от»: `Dog : Animal(...)` значит «Dog это вид Animal».
- `Animal(name, age)` справа от двоеточия означает «передай эти значения в конструктор родителя». Параметры `name` и `age` у `Dog` без `val` потому, что хранить их будет сам `Animal`.
- `override` («переопределить») пишется у метода потомка, который заменяет метод родителя. Без `override` Котлин выдаст ошибку.
- `super` («суперкласс», родитель) позволяет вызвать код родителя, например `super.sound()` выполнит версию из `Animal`.

### Полиморфизм: «один вызов, разное поведение»

Главная польза наследования в том, что потомков можно хранить в общем списке и обращаться к ним как к родителю. Каждый объект сам знает, как ему отвечать:

```kotlin
fun main() {
    val animals: List<Animal> = listOf(
        Dog("Рыжик", 4),
        Rat("Крыс", 1),
        Animal("Неизвестный", 2)
    )
    for (animal in animals) {
        animal.sound()      // для каждого сработает свой вариант sound()
    }
}
```

Программа не проверяет, кто перед ней, а просто просит `sound()`. Если завтра добавится кошка, этот цикл менять не придётся. Это называется **полиморфизмом** («много форм»).

### Проверка вида: is

Иногда нужно узнать, кто именно лежит в переменной. Для этого есть `is`:

```kotlin
for (animal in animals) {
    if (animal is Dog) {
        println("${animal.name} это собака")   // внутри ветки Котлин считает animal уже Dog
    }
}
```

Запись `x is Тип` читается «x является этим типом», а `x !is Тип` наоборот.

## Тема 15. Абстрактные классы и интерфейсы

Иногда родитель описывает понятие настолько общее, что создавать его объект не имеет смысла. Что такое просто «фигура»? Какого она размера? Есть только конкретные фигуры: круг, квадрат. Для таких случаев нужны абстрактные классы и интерфейсы.

### Абстрактный класс

**Абстрактный класс** (`abstract`) это «заготовка»: объект такого класса создать нельзя, он существует только для наследования. В нём можно описать:

- **абстрактные методы** без тела: родитель знает, что фигура должна уметь считать площадь, но не знает как. Потомки **обязаны** их реализовать;
- **обычные методы** с готовой реализацией, которые потомки получают как есть.

```kotlin
import kotlin.math.PI

abstract class Shape(val name: String) {
    abstract fun area(): Double        // тела нет: «как считать» решают потомки
    abstract fun perimeter(): Double

    fun describe(): String {            // обычный метод с реализацией
        return "Фигура: $name"
    }
}

class Circle(val radius: Double, name: String) : Shape(name) {
    override fun area() = PI * radius * radius
    override fun perimeter() = 2 * PI * radius
}

class Square(val width: Double, name: String) : Shape(name) {
    override fun area() = width * width
    override fun perimeter() = 4 * width
}

fun main() {
    // val s = Shape("Фигура")   // ОШИБКА: абстрактный класс создать нельзя
    val shapes = listOf(Circle(10.0, "Круг"), Square(5.0, "Квадрат"))
    for (s in shapes) println("${s.describe()}, площадь ${s.area()}")
}
```

У абстрактных классов слово `open` не нужно: они и так предназначены для наследования.

### Интерфейс

**Интерфейс** (`interface`) описывает **умение**, а не сущность. «Умеет летать», «умеет плавать», «умеет возвращать деньги». Сам по себе он ничего не хранит, а только обещает, какие методы будут у тех, кто его подключил.

```kotlin
interface Flyable {
    fun fly()                              // без тела: реализуют классы
    fun land() {                           // с телом: реализация по умолчанию
        println("Приземлился")
    }
}

interface Swimmable {
    fun swim()
}

class Bird(val name: String) : Flyable, Swimmable {   // через запятую можно подключить сколько угодно
    override fun fly() { println("$name машет крыльями") }
    override fun swim() { println("$name поплыла") }
    // land() не переопределяем: берётся версия по умолчанию
}

class Human(val name: String) : Flyable {
    override fun fly() { println("$name полетел") }
    override fun land() { println("Полёт был недолгим...") }   // а здесь заменили
}
```

Обратите внимание: после двоеточия интерфейс записывается **без скобок** (`Flyable`), а родительский класс **со скобками** (`Shape(name)`), потому что у класса надо вызвать конструктор.

### Чем отличаются

|  | Абстрактный класс | Интерфейс |
| --- | --- | --- |
| Смысл | «что это за вид сущности» | «что умеет» |
| Сколько можно наследовать | только один | сколько угодно |
| Хранит свои данные (свойства с состоянием, конструктор) | да | нет |
| Как проверить | `x is Shape` | `x is Flyable` |

Хороший признак: если слово «является» (круг **является** фигурой), это класс. Если слово «умеет» (птица **умеет** летать), это интерфейс. Птица и самолёт не родственники, но оба могут реализовать `Flyable`.

### Конфликт одинаковых методов

Если два интерфейса требуют метод с одним именем, класс обязан решить, что делать. Вызвать версию конкретного интерфейса можно так:

```kotlin
interface A { fun doSomething() { println("из A") } }
interface B { fun doSomething() { println("из B") } }

class C : A, B {
    override fun doSomething() {
        super<A>.doSomething()   // super<A> значит «версия именно из A»
    }
}
```

## Тема 16. data class и enum

### data class: класс для хранения данных

Часто класс нужен только для того, чтобы **хранить набор значений**: координаты точки, заказ, профиль. Для этого есть `data class`. Вы пишете одно слово `data`, а компилятор сам создаёт полезные методы:

- `toString()`: красивый вывод всех свойств;
- `equals()`: сравнение по содержимому;
- `copy()`: копия объекта с изменением выбранных полей;
- возможность «распаковать» объект в переменные.

```kotlin
data class Point(val x: Double, val y: Double)

fun main() {
    val p1 = Point(10.0, 20.0)
    val p2 = Point(10.0, 20.0)
    val p3 = Point(-10.0, 42.0)

    println(p1)            // Point(x=10.0, y=20.0), сам toString
    println(p1 == p2)      // true: содержимое одинаковое
    println(p1 == p3)      // false
    println(p1 === p2)     // false: это два РАЗНЫХ объекта в памяти
    println(p1 === p1)     // true: это один и тот же объект

    val moved = p1.copy(x = 15.0)   // копия, где изменили только x: Point(x=15.0, y=20.0)
    val (x, y) = p1                 // распаковка: x = 10.0, y = 20.0
}
```

Новое здесь:

- `==` сравнивает **по смыслу** (содержимому). У обычных классов без `data` он сравнивает ссылки.
- `===` (три знака) проверяет, что это **буквально один и тот же** объект, а не просто похожие. Применяется редко.
- `copy(...)` не меняет исходный объект, а создаёт новый. Поэтому в `data class` чаще пишут `val`: объект неизменяем, а для «изменения» берут копию.
- В скобках первичного конструктора у `data class` должно быть хотя бы одно свойство (`val` или `var`).

### enum: перечисление

`enum class` описывает **закрытый набор вариантов**: статусы заказа, дни недели, уровни доступа. Это надёжнее строк: опечатку в `"delivred"` компьютер не заметит, а несуществующий `OrderState.DELIVRED` не скомпилируется.

```kotlin
enum class OrderState(val value: String) {
    NEW("new"),
    PAID("paid"),
    DELIVERED("delivered"),
    CANCELLED("cancelled");     // после последнего варианта ставится ; если дальше идут методы

    fun next(): OrderState {
        return when (this) {    // this: текущий вариант, у которого вызвали метод
            NEW -> PAID
            PAID -> DELIVERED
            DELIVERED -> DELIVERED
            CANCELLED -> CANCELLED
        }
    }
}

fun main() {
    val state = OrderState.NEW
    println(state)             // NEW
    println(state.value)       // new, значение из конструктора
    println(state.name)        // NEW, имя варианта как строка
    println(state.ordinal)     // 0, номер варианта по порядку

    val after = state.next()   // PAID: метод вернул НОВЫЙ вариант
    println(after)

    for (s in OrderState.entries) println(s)   // перебор всех вариантов
}
```

- Варианты пишутся ЗАГЛАВНЫМИ буквами по традиции и всегда через имя перечисления: `OrderState.NEW`.
- Варианты enum нельзя «изменить»: `state.next()` вернёт другой вариант, а сам `state` останется прежним. Поэтому результат надо сохранить: `val after = state.next()`. Если вызвать `state.next()` и никуда не записать результат, ничего не произойдёт (так в примере курса `orderState.changeState(...)` ничего не делал).
- В вашем примере с курса метод получал параметр `state` и делал `when (state)`, поэтому текущий вариант (`this`) вообще не использовался. Правильно, как выше, смотреть на `when (this)`.
- `when` по enum очень удобен: если вы не перечислили все варианты и не добавили `else`, Котлин покажет ошибку. Так вы не забудете новый статус, когда он появится.
- `OrderState.entries` даёт список всех вариантов (в старых версиях Kotlin пишут `OrderState.values()`).

## Тема 17. Модификаторы видимости и модули

**Модификатор видимости** отвечает на вопрос «кто имеет право пользоваться этим классом, функцией или свойством?». Мы уже встречались с `private`, теперь соберём всё вместе.

| Модификатор | Кто видит |
| --- | --- |
| `public` (по умолчанию, писать не нужно) | все, из любого места |
| `private` | только внутри того же класса (а для функции или класса вне класса: только внутри того же файла) |
| `protected` | сам класс и его потомки; снаружи недоступно |
| `internal` | всё, что находится в том же **модуле** |

```kotlin
open class Account {
    private var pin = "1234"            // видно только внутри Account
    protected var balance = 100.0       // видно в Account и в его потомках
    internal fun auditLog() { }         // видно во всём модуле
    fun showBalance() { }               // public: видно всем
}

private fun helper() { }                // видно только внутри этого файла
```

### Что такое модуль

**Модуль** это отдельная часть проекта со своей сборкой: у неё свои исходники и свои зависимости. В большом приложении обычно несколько модулей: например, «интерфейс» и «работа с данными». В IDEA модули видны в окне Project как отдельные папки верхнего уровня и создаются через **File → New → Module**.

Зачем нужен `internal`: модуль хочет показать наружу только то, что действительно нужно другим модулям (`public`), а свою внутреннюю «кухню» спрятать (`internal`). В примере курса класс `UI` импортировался из другого модуля, потому что он `public`, а класс `Data1` из другого модуля использовать было нельзя, потому что он помечен `internal`.

### Важный нюанс

В пределах **одного модуля** `internal` ничего не скрывает: все файлы одного проекта, который вы создали одним мастером IDEA, это один модуль. Поэтому в одном проекте вы увидите разницу только между `private` и остальными, а чтобы увидеть, как `internal` не пускает чужой модуль, нужен именно второй модуль (если подключить его как зависимость в **File → Project Structure → Modules → Dependencies**).

### Практическое правило

Начинайте с самого закрытого варианта (`private`) и открывайте только то, что действительно нужно снаружи. Так проще менять код: вы точно знаете, кто может им пользоваться.

## Шпаргалка: символы и ключевые слова

Если встретили в коде непонятный знак, загляните сюда.

| Что | Значение | Пример |

| `=` | положить значение в переменную | `val a = 1` |
| `==` / `!=` | равно / не равно (по содержимому) | `a == b` |
| `===` | тот же самый объект | `p1 === p2` |
| `: Тип` | «имеет тип» | `val a: Int = 5` |
| `: Родитель(...)` | «наследуется от» (после имени класса) | `class Dog : Animal()` |
| `?` в типе | значение может быть null | `String?` |

| `?:` | запасное значение, если слева null | `name ?: "нет"` |
| `!!` | «уверен, что не null» (опасно) | `name!!.length` |
| `..` | диапазон «от и до» | `1..5` |
| `until`, `downTo`, `step` | границы и шаг диапазона | `1 until 5`, `10 downTo 1 step 2` |

| `this` | этот самый объект | `this.age = age` |
| `super` | родитель | `super.sound()` |
| `override` | заменить метод родителя | `override fun sound()` |
| `open` | разрешить наследовать или переопределять | `open class Animal` |
